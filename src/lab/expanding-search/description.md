A search field that becomes its own results panel. Press Enter and the pill grows into a card: the input is pinned by its top edge, so it never moves and the space for results is revealed below it. A skeleton fills that space while the (fake) search runs, then the rows rise into place and a single highlight jumps between them as you hover.

Two rounds of prototypes came before this. The first compared techniques: skeleton or spinner, a height reveal or a `clip-path`/`scaleY` morph, one shared highlight or a per-row fade, staggered or all-at-once rows. The skeleton won because it pre-draws the shape of the results, so the swap reads as filling in rather than replacing; the shared highlight won because it gives the list one object to track, the same idea as the sliding tabs demo. The second round stayed inside those choices and settled the feel: a crisp 320ms growth with no bounce, and a highlight that does not slide at all but jumps to the row with only its opacity easing, because sliding, even at 120ms, made hovering feel a step behind the pointer. The card originally grew *upward* from a bottom-anchored input; it was flipped once keyboard navigation went in, because the best result sat at the far end from the input and ArrowDown walked away from it. With the input on top, the best result is nearest the field and ArrowDown reaches it first. The other options are still wired up behind the DialKit panel in dev, so they are one select away if you want to compare.

The skeleton is built from the result row's exact box, same padding, gap and line heights, so the card is the same height to the pixel while loading and once results are in; nothing shifts when they swap. The list is keyboard-navigable the way a combobox is: ArrowDown from the input steps into the results, the arrows move within them, and Escape collapses back to the input.

The sequence is a small reducer, `idle → expanding → loading → results`, with a request id threaded through the fake fetch so that pressing Escape or searching again mid-flight can never let a stale response reopen the card. The height animation itself is what moves the machine from `expanding` to `loading`, so the skeleton only appears once the card has finished growing. Under `prefers-reduced-motion` the card still changes size, but instantly, and the rows crossfade without rising or staggering.
