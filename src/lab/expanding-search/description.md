A search field that becomes its own results panel. Press Enter and the pill grows *upward* into a card: the input is pinned by its bottom edge, so it never moves and the space for results is revealed above it. A skeleton fills that space while the (fake) search runs, then the rows rise into place and a single highlight slides between them as you hover.

Four variations were prototyped before this one was picked: the loading state as skeleton or spinner, the growth as a height reveal or a `clip-path`/`scaleY` morph, the hover as one shared highlight or a per-row fade, and the results staggering in or arriving at once. The skeleton won because it pre-draws the shape of the results, so the swap reads as filling in rather than replacing. The shared highlight won because it gives the list one object to track, the same idea as the sliding tabs demo. The other options are still wired up behind the DialKit panel in dev, so they are one select away if you want to compare.

The sequence is a small reducer, `idle → expanding → loading → results`, with a request id threaded through the fake fetch so that pressing Escape or searching again mid-flight can never let a stale response reopen the card. The height animation itself is what moves the machine from `expanding` to `loading`, so the skeleton only appears once the card has finished growing. Under `prefers-reduced-motion` the card still changes size, but instantly, and the rows crossfade without rising or staggering.
